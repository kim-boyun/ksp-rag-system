# 아키텍처 개요

## 🏗️ 시스템 구조

KSP RAG System은 **역할 분리 아키텍처**를 채택하여 운영 서버와 GPU 서버를 명확히 분리합니다.

```
┌─────────────────────────────────────────────────────────────────┐
│                    운영 서버 (App Server)                        │
│                    (이 레포지토리)                                │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌──────────────┐  ┌──────────────┐  ┌──────────────┐          │
│  │ Elasticsearch │  │   RAG App    │  │  Streamlit   │          │
│  │   (9200)     │  │   (Python)   │  │     UI       │          │
│  └──────┬───────┘  └──────┬───────┘  └──────┬───────┘          │
│         │                  │                  │                   │
│         └──────────────────┴──────────────────┘                   │
│                            │                                      │
│                    ┌───────▼────────┐                             │
│                    │  인덱싱/임베딩  │                             │
│                    │  (BGE 모델)    │                             │
│                    └────────────────┘                             │
│                                                                   │
└───────────────────────────┬─────────────────────────────────────┘
                            │ HTTP 요청
                            │ (LLM inference)
                            │
┌───────────────────────────▼─────────────────────────────────────┐
│                    GPU 서버 (별도 서버)                           │
│                    (ops/gpu/docker-compose.yml)                 │
├─────────────────────────────────────────────────────────────────┤
│                                                                   │
│  ┌──────────────────────────────────────────────┐               │
│  │            vLLM Inference API                │               │
│  │         (OpenAI-compatible)                   │               │
│  │         Port: 8000                            │               │
│  │                                               │               │
│  │  Endpoints:                                    │               │
│  │  - /v1/completions                            │               │
│  │  - /v1/chat/completions                       │               │
│  │  - /health                                    │               │
│  └──────────────────────────────────────────────┘               │
│                                                                   │
└─────────────────────────────────────────────────────────────────┘
```

## 📦 컴포넌트 역할

### 운영 서버 (App Server)

**위치**: 이 레포지토리 (`docker-compose.yml`)

**컴포넌트**:
1. **Elasticsearch** (포트 9200)
   - 하이브리드 검색 (BM25 + kNN dense vector)
   - 문서 저장 및 검색 인덱스 관리

2. **RAG App** (Python 컨테이너)
   - 문서 인제스트 (PDF → chunks)
   - 임베딩 생성 (BGE 모델)
   - Elasticsearch 인덱싱
   - RAG 파이프라인 실행 (검색 → 리랭크 → LLM 호출)

3. **Streamlit UI** (포트 8501)
   - 웹 기반 질의응답 인터페이스
   - 검색 결과 및 인용 표시

**환경 변수**: `.env.server`
- `LLM_PROVIDER=server_http`
- `SERVER_LLM_BASE_URL=http://<GPU_SERVER_IP>:8000`
- `ELASTIC_HOST=elasticsearch` (또는 `host.docker.internal`)

### GPU 서버

**위치**: 별도 서버 (`ops/gpu/docker-compose.yml`)

**컴포넌트**:
1. **vLLM** (포트 8000)
   - LLM 모델 추론 (GPU 가속)
   - OpenAI-compatible HTTP API 제공
   - 모델 캐싱 및 배치 처리

**환경 변수**: `.env.gpu` (선택 사항)
- `SERVER_LLM_MODEL=openai/gpt-oss-120b`
- `GPU_MEMORY_UTILIZATION=0.9`

## 🔄 네트워크 흐름

### 1. 문서 인제스트 (운영 서버 내부)

```
PDF 파일
    ↓
RAG App (ingest)
    ↓
텍스트 추출 → 청킹 → 임베딩 생성 (BGE)
    ↓
Elasticsearch 인덱싱
```

### 2. RAG 질의 (운영 서버 → GPU 서버)

```
사용자 질문 (Streamlit UI)
    ↓
RAG App (ask)
    ↓
Elasticsearch 검색 (BM25 + kNN)
    ↓
리랭크 (선택 사항)
    ↓
HTTP 요청 → GPU 서버 vLLM (http://<GPU_IP>:8000/v1/chat/completions)
    ↓
LLM 응답 생성
    ↓
답변 + 인용 반환
```

### 3. 로컬 개발 모드 (운영 서버만)

```
사용자 질문
    ↓
RAG App (local mode)
    ↓
로컬 인덱스 검색 (BM25 + FAISS)
    ↓
OpenAI API 호출 (외부)
    ↓
답변 반환
```

## 🌐 포트 및 네트워크

### 운영 서버 포트

| 서비스 | 포트 | 용도 | 접근 |
|--------|------|------|------|
| Elasticsearch | 9200 | 검색 엔진 | 내부 네트워크 |
| Streamlit UI | 8501 | 웹 UI | 외부 접근 가능 |
| RAG App | - | 백엔드 | 내부 네트워크 |

### GPU 서버 포트

| 서비스 | 포트 | 용도 | 접근 |
|--------|------|------|------|
| vLLM API | 8000 | LLM 추론 | 운영 서버에서 접근 |

### 방화벽 규칙

**운영 서버**:
- 인바운드: 8501 (Streamlit UI)
- 아웃바운드: GPU 서버 8000 포트 접근 필요

**GPU 서버**:
- 인바운드: 8000 (vLLM API, 운영 서버에서만 접근)
- 아웃바운드: 인터넷 (모델 다운로드)

## 🔐 보안 고려사항

1. **네트워크 격리**: GPU 서버는 운영 서버에서만 접근 가능하도록 설정
2. **인증**: vLLM API에 인증 추가 고려 (프로덕션 환경)
3. **HTTPS**: 프로덕션 환경에서는 HTTPS 사용 권장

## 📊 데이터 흐름

### 문서 저장

```
PDF → chunks.jsonl → Elasticsearch
                    └─> 로컬 인덱스 (로컬 모드)
```

### 검색 흐름

```
Query → Embedding (BGE) → 검색 (BM25 + kNN) → Top-K 문서
```

### LLM 호출

```
검색된 문서 + Query → Prompt 생성 → vLLM API → 응답 생성
```

## 🎯 왜 이렇게 분리하는가?

### 1. 비용 최적화
- GPU 서버는 추론 시에만 사용 → 유휴 시간 비용 절감
- 운영 서버는 CPU 기반으로 충분 → 저렴한 인스턴스 사용 가능

### 2. 운영 편의성
- 각 서버의 독립적인 스케일링 및 업데이트 가능
- GPU 서버 장애 시 운영 서버는 계속 동작 (검색 기능 유지)
- 모니터링 및 로그 관리 분리

### 3. 성능 최적화
- GPU 서버는 추론에만 집중 → 최대 처리량 확보
- 운영 서버는 검색/인덱싱에 집중 → 응답 시간 단축
- 네트워크 지연 최소화 (필요 시 동일 네트워크 배치)
